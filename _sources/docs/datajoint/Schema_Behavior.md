# Schema - mousear_behavior

**Module**: `dj_pipeline/schemas/mousear_behavior.py`

The core behavioral schema. Imports all data from Unity game sessions and computes trial-wise summaries.

---

## UnityGameType

**Type**: `dj.Lookup`

| Field | Type | Description |
|-------|------|-------------|
| `game_type` | varchar(64) PK | Unique name of the game type |
| `description` | varchar(256) | Description |

**Contents**: `MouseHockey`, `SequencePlaces`, `TouchDestroy`, `TouchMove`, `RewardAssociation`

---

## UnityAgentType

**Type**: `dj.Lookup`

| Field | Type | Description |
|-------|------|-------------|
| `behavior_type` | varchar(32) PK | Unique name of the behavior agent |
| `description` | varchar(256) | Description |

**Contents**:

| behavior_type | Description |
|---------------|-------------|
| `TTLInput` | Screen sync TTL input — carries ITI/initiation state flags |
| `TouchInput` | Touch data from touchscreen manager |
| `DLCInput` | DeepLabCutLive! pose estimation input |

---

## UnitySession

**Type**: `dj.Imported`  **Depends on**: `Dataset`

Master table for a single behavioral session. Populated by reading `UnityData_<dataset_id>.json`.

| Field | Type | Description |
|-------|------|-------------|
| `dataset_id` | FK → Dataset | Session identifier |
| `game_type` | FK → UnityGameType | Type of Unity game played |
| `session_duration` | float32 | Session duration in minutes |
| `session_start_time` | float64 | Unix timestamp of session start (steps are relative to this) |
| `nr_trials` | int32 | Number of trials (unique episodes) |
| `nr_rewarded_trials` | int32 | Number of rewarded trials |
| `mouse_weight` | float32 | Mouse weight in grams |
| `session_note` | varchar(256) | Free-text session note |
| `params` | json | All game parameters used in this session |

### UnitySession.UnityData

Step-by-step game data for the entire session.

| Field | Type | Description |
|-------|------|-------------|
| `episode` | blob | Episode number at each game step |
| `step` | blob | Game step index |
| `step_time` | blob | Step timestamp in seconds (relative to session start) |
| `reward` | blob | Reward flag at each step (1 = rewarded) |
| `terminal` | blob | Terminal flag at each step (1 = episode end) |

### UnitySession.UnityAgentBehavior

Actions and observations for each input agent at each step. One row per `(session, behavior_type)`.

| Field | Type | Description |
|-------|------|-------------|
| `behavior_type` | FK → UnityAgentType | Which agent (TTLInput / TouchInput / DLCInput) |
| `action` | blob | Actions sent to Unity at each step |
| `state` | blob | Observations received from Unity at each step |

### UnitySession.DlcData

Timing of DLC data delivered to the game (not the pose itself — that's in `DlcLiveData`).

| Field | Type | Description |
|-------|------|-------------|
| `dlc_times` | blob | Array of `[recv_time, proc_time]` per step |

### UnitySession.TouchData

Touch input from the touchscreen.

| Field | Type | Description |
|-------|------|-------------|
| `touch_read_time` | blob | Timestamps when touch data was read |
| `pixel_xy` | blob | Pixel coordinates of touch points (x, y) |
| `screen_xy` | blob | Screen-normalized coordinates (x, y) |
| `vector_prop` | blob | Vector properties: heading, speed, vx, vy |

### UnitySession.ScreenTTLData

TTL barcode signals generated by the screen for hardware synchronization.

| Field | Type | Description |
|-------|------|-------------|
| `ttl_times` | blob | Timestamps of each TTL pulse (perf_counter) |
| `ttl_counters` | blob | Counter ID of each pulse |
| `ttl_values` | blob | 8-bit value of each pulse |

### UnitySession.TeensyData

All data recorded by the Teensy microcontroller.

| Field | Type | Description |
|-------|------|-------------|
| `teensy_outputs` | blob | Raw output log: `[[timestamp, output_name], ...]` |
| `t_host` | blob | Host timestamps |
| `t_dev_est` | blob | Estimated device timestamps |
| `t_dev_us` | blob | Device timestamps in microseconds |
| `photodiode` | blob | Photodiode (analog) readings |
| `barcodettl` | blob | Barcode TTL detections from screen |
| `watervalve` | blob | Water valve opening events |
| `syncttl` | blob | Digital photodiode sync signal |
| `lux` | blob | BH1750 lux sensor readings |
| `luxtimestamp` | blob | BH1750 timestamps in microseconds |

### UnitySession.UnityMessage

Key-value messages sent from Unity to Python during the session.

| Field | Type | Description |
|-------|------|-------------|
| `kv_messages` | blob | Full list of KV messages |

### UnitySession.UnityRuntimeParams

Records parameter changes that occurred during the session (e.g., from the rules scheduler).

| Field | Type | Description |
|-------|------|-------------|
| `param_id` | int32 PK | Sequential identifier |
| `episode` | int32 | Episode when the change occurred |
| `params` | json | Full parameter dict at that point |

## TrialInfo

**Type**: `dj.Computed`  **Depends on**: `UnitySession`

Extracts trial-wise boundaries and outcomes from the step-level session data.

| Field | Type | Description |
|-------|------|-------------|
| `trial_id` | int32 PK | Trial index within the session |
| `start_step` | int32 | First step of actual gameplay (after ITI/initiation) |
| `end_step` | int32 | Last step of the trial (includes post-trial ITI) |
| `iti_start_step` | int32 | Step where ITI begins (end of gameplay) |
| `initiation_end_step` | int32 | Step where initiation phase ends |
| `reward_received` | bool | Whether a reward was delivered in this trial |
| `trial_params` | json | Game parameters active during this trial |

### Trial Structure

```
Episode N:
│← initiation →│← gameplay →│← ITI →│
               ↑             ↑       ↑
         start_step   iti_start_step  end_step
         (= initiation_end_step
            if no initiation phase)
```

ITI and initiation flags come from `TTLInput` observations:
- `TTLInput.state[1]` — ITI flag (1 = in ITI)
- `TTLInput.state[2]` — Initiation flag (1 = in initiation)

### Method: `get_trial_data(key, trial_id, data_type, beh_type)`

Utility to extract action or state arrays for a specific trial:

```python
from dj_pipeline.schemas.mousear_behavior import TrialInfo

# Get DLC actions for trial 5
data = TrialInfo.get_trial_data(
    key={"dataset_id": "Tick_20260210_141820"},
    trial_id=5,
    data_type="action",
    beh_type="DLCInput",
)
# Returns dict: {"DLCInput": array[start_step:end_step]}
```

| Parameter | Description |
|-----------|-------------|
| `key` | DataJoint key identifying the session |
| `trial_id` | Trial index |
| `data_type` | `"action"` or `"state"` |
| `beh_type` | `"DLCInput"`, `"TouchInput"`, `"TTLInput"`, or `None` for all |
